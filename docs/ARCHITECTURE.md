# A graph you can inhabit

Hub Tech Codex is a next-generation interface for discovering and relating the open software ecosystem, initially bounded to GitHub. It does not replace GitHub or ingest Atlas's private internals.

## Ownership

| Owner | Owns | Boundary |
| --- | --- | --- |
| GitHub / source maintainers | repository content, revision history, releases and source declarations | an observation is not source custody |
| Hub Tech Codex | discovery observations, relationship descriptions, navigational projections | does not create execution/ownership grants |
| Diamond | authorised target standing, closed operations, findings and receipts | local demo cannot bypass the real broker |
| Atlas | independent stewardship, identity/authority references and governed federation | no shared mutable registry or copied proprietary implementation |
| Domain hub | its domain events, privacy, lifecycle and current truth | domain lens references rather than replaces that truth |

## Representation stack

JSON gives stable IDs, relationships, source references and explicit standings. HTML is semantic interaction. CSS supplies the interface layout without semantic authority. Native WebGL supplies actual three-dimensional meshes, perspective, depth testing and lighting; semantic HTML labels remain selectable source projections. JavaScript mediates camera/picking, selection, public metadata observations and bounded local inventory. Rendering is not execution permission.

The relation graph may have cycles and multiple parents. Visual nesting is a projection; it never duplicates a child identity or implies ownership. Reciprocal navigation derives from the same edge. Constellation, directory and within-hub views use identical IDs. Six-faced space is an experimental lens, not an invariant.

## Standings

`observed` means a named fact was obtained at a named time, not that it is trustworthy. `declared` records someone's description. `planned` stays absent at runtime. `evaluated`, `authorised`, `connected` require separate evidence and scoped contracts; this seed assigns none automatically. Discovery/evaluation/permission/connection are not one scalar ladder.

## Source observation

The adapter accepts an explicitly selected owner/repository or credential-free GitHub repository URL. It calls the fixed public GitHub REST host, reads repository metadata and pins the default-branch revision. It rejects private/mismatched identities, redirects, non-JSON/oversized bodies and typed source failures. It runs no downloaded code. Repository licence metadata is a declaration, not a legal compatibility determination or integration grant. Observation is session-local in the UI; the CLI emits JSON for intentional preservation.

## Diamond proof

The demonstration parses an operator-supplied package manifest using the public operation name `inventory.dependencies`. Its accepted target is a visibly labelled fixture with operation/window constraints. Package scripts are ignored, not executed. Receipts explicitly declare `local-inert-demo` and `grantsAuthority:false`. No Diamond or Atlas endpoint is called. It does not establish dependency safety or advisory completeness.
