# Hub environment V0 — approved direction

User direction: populate Hub Tech Codex using GitHub as the bounded source and route, build the mapped topology and appropriate continuing development branches. The preceding in-chat design was accepted on 7 October 2026. Execute within that scope.

## Ownership
Hub Tech Codex owns its discovery observations, typed relationship descriptions and navigational projections. GitHub owns repository source/history. Diamond owns operation execution, scoped target approval and findings. Atlas retains stewardship authority. Nothing here copies proprietary Atlas code or changes another product's authority.

## First complete traversal
Public GitHub repository → timestamped metadata observation → one stable node → reciprocal relationship navigation → bounded local dependency inventory → inspectable demonstration receipt. No downloaded code executes. No live Diamond transport is claimed. The local inventory demonstrates the public operation shape; Diamond authority review remains an explicit local simulation.

## Environment
JSON stores graph descriptions; HTML gives semantic interactive surfaces; CSS provides depth, layout and continuity; JavaScript controls navigation and public metadata reads. List, constellation and nested surfaces use the same stable IDs. Navigation history restores lens/filter/selection. A hub can contain/reference other hubs without duplicating identity; cycles are allowed in relationships and guarded in traversal. Six faces are experimental, never constitutional.

## Constraints
- Node.js >=22; zero runtime/package dependencies.
- Only explicitly selected public GitHub repositories are fetched; fixed api.github.com host, no credentials in browser.
- Discovery is not licensing permission, installation, trust or execution authority.
- Invalid schema, dangling edges, duplicate identities and unsupported operations fail closed.
- External labels render as text, never HTML. External links must be credential-free HTTPS.
- Historical concept art is reference only; no health, financial, operational or verification claims are inferred from it.
- Respect reduced motion, keyboard navigation, mobile viewport and colour-independent status labels.

## Development topology
Main holds coherent tested baseline. Independent continuing branches cover GitHub intelligence, Diamond adapters, surfaces, relationship/event continuity, domain lenses, agent interfaces and federation. Dependencies and acceptance checks are machine-readable, without suggesting a branch is a deployed capability.

## Verification
Node tests cover graph invariants/cycles, navigation restoration, GitHub API refusal and schema/error boundaries, local inventory authority refusal and receipts. Browser smoke verifies filters, selection, back, import errors and demo traversal at mobile/desktop sizes. No live privileged or third-party target operations.
