# Contextual symbols and execution containment

Approved direction: turn the October 8 research and visual references into
bounded implementation, preserving source ownership and existing identities.

## Public symbol contract

Add a data-only catalog of candidate interpretations. Every interpretation has
a persistent ID, explicit context and revision, meaning, preserved invariants,
failure examples and source attribution standing. Bind selected interpretations
to existing fixture body IDs; do not infer bindings from labels or geometry.
The same motif may carry different meanings in different contexts. Resolution
requires both context and revision and refuses ambiguous matches. Historical
bindings retain their selected revision. These records grant no authority.

Expose the records in the existing evidence inspector without changing the
renderer. Reject malformed or dangling bindings; an unavailable symbol catalog
must leave the independent event field usable and show its own absence.
Use text nodes for imported strings. Do not copy image assets or third-party
text; source attribution and asset rights for the supplied references are unknown.

## Private execution boundary

Keep the Diamond change in private Atlas. One passive probe issues one GET,
with redirects disabled before dispatch. A redirect response is inconclusive
for downstream-resource evaluation. Injected transports must honor manual mode;
responses from a different final URL are rejected, including same-origin path
changes. A response check cannot undo a non-conforming transport's effects.

## Execution and evidence

1. Reproduce the redirect escape with loopback listeners, then fix the transport
   and executor policy. Run every Diamond test available from the pinned snapshot.
2. Write behavioral symbol tests before the module: contextual ambiguity,
   historical revisions, explicit subject binding, malformed provenance and
   authority refusal. Implement the catalog, fixture and inspector consumer.
3. Run the Hub's full test and check scripts and a browser smoke check. Review
   the actual diffs, then publish separate draft PRs against their owning repos.

No new dependencies, canonical identities, executable symbol actions, automatic
doctrine promotion or merge/deployment are part of this change.
